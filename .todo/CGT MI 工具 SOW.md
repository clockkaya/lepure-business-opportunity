这份需求提案核心在于 **“非结构化数据的结构化提取与分发”**。作为架构师，我给出的定性是：**这是一个典型的“重工程、轻AI”项目**。

核心挑战不在于 AI 的理解能力，而在于**微信公众号闭源生态的数据抓取**。

---

## 一、 技术可行性定性

- **模式选择： 混合模式 (Hybrid Logic)**。利用 Python 脚本进行自动化调度、网页解析与消息分发；利用 LLM（大语言模型）进行文本摘要、实体提取（公司/项目/阶段）及分类过滤。
  
- **AI 必要性评估：** 只有在**“将新闻散文转化为结构化表格数据”**以及**“多源信息的去重合并”**环节，AI 是不可替代的。早期的关键词过滤（Regex）无法准确判断融资规模或临床阶段的细微差别，因此需要引入 LLM。
  

## 二、 核心技术栈 (Tech Stack)

- **语言/框架：** `Python 3.10+` + `Pandas` (数据处理) + `BeautifulSoup4/Playwright` (内容解析)。
  
- **AI 工具：** `Dify` (工作流引擎) + `DeepSeek-V3` / `GPT-4o-mini` (兼顾成本与语义提取能力)。
  
- **数据接入：** 微信公众号由于闭源，建议通过 `WeChat2RSS` 或第三方抓取服务（如：瓦斯、各色 RSS 订阅器 API）获取内容。
  
- **部署/载体：** `企业微信机器人 Webhook` + `本地/云端定时任务 (Cron Job)`。
  

## 三、 详细实施逻辑 (Detail Logic)

### 1. 数据准备

- **微信内容采集：** 放弃自研微信爬虫（成本极高且极易封号）。优先使用 RSS 聚合工具订阅需求中提到的“医麦客”、“细胞与基因治疗前沿”等列表。
  
- **清洗：** 脚本定期轮询 RSS 更新，获取文章 URL，使用 Python `newspaper3k` 库提取正文纯文本，过滤掉广告和底部引导语。

### 2. 工作流逻辑 (Dify Workflow)

- **Step 1 (分类器)：** 输入正文。判断是否属于“投融资”、“临床进展”、“政策法规”、“友商动态”四类之一。如果不属于，直接丢弃（减少后续 Token 消耗）。
  
- **Step 2 (提取器)：** 针对命中类别的文章，由 LLM 提取字段：`公司名称`、`技术路线`（MSC/IPSC/AAV等）、`项目阶段`（IND/IIT/I期等）、`关键动作`。
  
- **Step 3 (去重检查)：** 将提取结果与本地 `SQLite/Excel` 进行 MD5 指纹对比，防止同一条新闻跨频道、跨日期重复推送。
  

### 3. Prompt 策略

- **角色定位：** 你是一个资深的 CGT（细胞与基因治疗）行业分析师。
  
- **核心指令：** > “请从以下文章中提取信息。如果涉及多个项目，请以 JSON 数组形式输出。如果文章不含具体的客户项目进展，请返回 null。”
  
- **输出控制：** 严格限定 JSON 结构。
  
- **Temperature 设置：** `0.1` (确保结构化输出的稳定性，严禁 AI 自由发挥)。

## 五、 避坑指南 (Critical Pitfalls)

- **微信反爬风险：** **千万不要试图自己写 Python 脚本去模拟微信客户端抓取**。微信对高频请求的封禁是账号级别的。务必使用现成的、付费的第三方抓取服务作为“缓冲层”。
  
- **字段幻觉问题：** CGT 行业术语极多，AI 可能会混淆 **“IIT (研究者发起的临床试验)”** 与 **“I期临床”**。需要在 Prompt 中提供 `Few-shot` (少量示例) 进行引导，并建立专业名词典进行校验。
  
- **消息轰炸：** 建议早晚各推送一次汇总（Daily Digest），而不是“一有就推”。否则对于关注了几十个公众号的销售来说，企微机器人会变成骚扰来源，降低工具的使用意愿。
